smith_agent repo mode: scoped worktree drafting

Built and tested 2026-09-12. Adds a --repo mode to scripts/smith_agent.py so the fleet can draft against a real repository under a declared, mechanically enforced write scope, instead of only in a throwaway sandbox. Borrowed from claude-vibe-squad's task contract and commit-time scope gate; everything else in that project stays unadopted.

Why this, and why now

Today smith_agent.py takes --workdir and treats it as a sandbox. To use the fleet on a real repo, Claude copies files in, copies results out, and re-reads everything, because nothing bounds what the model touched. That re-read is the reason the execution half stays on Claude. Part of that is a correct policy and part of it is just a missing gate.

A declared write scope plus a settlement gate replaces "Claude re-read all of it" with "the diff is provably inside these paths, and here is the patch". The draft/verify split does not change: the fleet drafts, Claude reads the patch and applies it.

The load-bearing insight

A scope check inside write_file is not a gate. run_command hands the model a bash shell (smith_agent.py line 168). echo x > README.md, sed -i, rm, git checkout all write files without touching write_file at all. Any check at write time is advisory.

The only sound gate is the net diff, computed at settlement, against a recorded base commit.

So both, for different jobs:

  • Advisory at write time. write_file refuses out-of-scope paths with an error string the model can read and correct from. Fast feedback, keeps the run productive.
  • Authoritative at settle time. The diff decides. Nothing the model does during the run can move this gate.

Design

New flags

Flag Meaning
--repo PATH Target git repo. Mutually exclusive with --workdir.
--write-scope GLOB Repeatable. Required in repo mode.
--read-scope GLOB Repeatable. Advisory only, see below.
--allow-delete Permit deletions and renames-away in the settled diff. Default: refuse.
--carry-ignored PATH Repeatable. cp -R a gitignored asset into the worktree.
--contract FILE Task contract supplying all of the above plus the prompt. Replaces --prompt-file.
--settle MODE patch (default), branch, or none.

--read-scope shapes the brief and filters list_files. It is not a boundary, because run_command can read anything in the worktree. Documented as advisory so nobody later mistakes it for containment.

The task contract

The one format worth borrowing from Vibe Squad. Front matter plus prose body, one file:

---
model:        glm-5.3
backend:      openai
base_url:     https://api.z.ai/api/coding/paas/v4
api_key_env:  ZAI_API_KEY
completions_path: /chat/completions
write_scope:  ["Sources/Engine/**.swift"]
read_scope:   ["Sources/**", "Tests/**"]
allow_delete: false
verify:       "swift test --filter EngineTests"
tag:          code-edit
---
Fix the off-by-one in the loop-point calculation so a loop that ends on the
final frame does not wrap. Add a test that fails before your change.

The value is that the bound is reviewable before the run and reproducible after it. One file to hand back and forth, and it diffs cleanly when a run gets retried with a tighter scope. Parsed with a ~15 line front-matter reader, no YAML dependency, since the fields are scalars and flat string lists.

Lifecycle

1. Preflight — refuse at launch, not retroactively.

  • --repo is a git repo; record base = git rev-parse HEAD.
  • write_scope non-empty. Reject **, *, .git/**, and any glob resolving outside the repo. An unbounded scope is the same as no scope, so it fails rather than silently passing everything.
  • Refuse if a worktree already exists at the target path, which is what a crashed earlier run leaves behind.
  • A dirty main tree is fine and is not checked. The worktree comes from base and is independent of the working tree.

2. Isolate.

git -C repo worktree add --detach <scratch>/wt-<ts>-<rand> <base>, and --workdir becomes that path. The existing loop runs unchanged. The random suffix matters: a bare timestamp collides when two runs start in the same second, which preflight then refuses as a leftover worktree.

⚠ --carry-ignored uses cp -R, never a symlink. Symlinking gitignored assets into a worktree once left the source tree holding self-referential symlinks after git worktree remove, with 114M and 478M model directories no longer reachable there. The mechanism was never established, so the rule is behavioral: copy, or do not bring it in.

3. Run.

Two guards added to the existing tools:

  • write_file gains the advisory scope check, plus a hard deny on any path under .git. In a linked worktree .git is a file holding the gitdir pointer; overwriting it breaks the worktree in a way that reads as a git bug.
  • DENY gains git push, git remote, git config --global, and gh . Read-only git stays available, since the model legitimately wants git status and git diff.

4. Settle.

git -C wt add -A
git -C wt diff --cached --name-status <base>

Diffing against the recorded base, not against worktree HEAD, is what makes this sound. A model that commits, amends, or checks out cannot hide a change from the gate, because the gate never consults worktree HEAD.

Then:

  • Violations are paths not matching any write_scope glob, plus D and rename-away status when --allow-delete is absent.
  • An empty diff is a failure, not a pass: stop = "finish_no_diff", settled = false. This supersedes the existing did_write flag in repo mode, since did_write only sees write_file and a run_command-only run would otherwise report a false completion. Same principle as the current finish_no_write downgrade, applied to the shell path.
  • A clean diff writes <scratch>/wt-<ts>.patch from git diff --cached --binary <base>.
  • A dirty diff writes .violations.json and leaves everything in place.
  • Build artifacts the verify command itself creates (__pycache__, *.pyc, .pytest_cache, .DS_Store) are unstaged rather than failed, and reported in the summary as artifacts. This was not in the original design and came out of the first end-to-end run: the task tells the model to run pytest, pytest writes __pycache__, and the gate failed an otherwise correct run. Reported rather than dropped, so nothing is hidden.
  • A settle reason never masks a loop failure. An HTTP 404 that produced no diff is an error, not "the model changed nothing", so the loop's own stop survives in loop_stop and an errored run is never relabelled finish_no_diff. Also found end-to-end, where a 404 read as a clean no-op run.

5. Teardown.

Remove the worktree only on a clean pass, and only after the patch is written. On any violation, leave it and print the path, because the whole point is inspecting what went wrong. When --carry-ignored was used, verify the source tree with ls -la before and after removal, never du, which reports 0B for a broken symlink and reads as success.

Output

summary JSON and the ledger record both gain settled, base, files[], violations[], and patch. stop gains finish_no_diff and scope_violation. The gap report and verdict.py keep working unchanged, since the tag field is untouched.

What this buys, and what it does not

Does: a mechanical bound on blast radius that Claude can check in one glance instead of re-reading a whole diff; deletions refused by default, consistent with the no-deletion rule; a patch Claude reads and applies rather than a merge that already happened.

Does not: contain a hostile model. run_command is a shell, and a model that wanted to escape the worktree could. This bounds carelessness, not malice. The settle gate is the backstop, and it catches the careless case completely.

Verification plan

Lifecycle probes, not a compile. Each is a throwaway "model does X, what must be true" script, and P3 is the one that proves the design is pointed at the right thing.

Probe Scenario Expected
P1 In-scope edit Settles, patch applies to a clean checkout
P2 Out-of-scope write via write_file Advisory refusal, model self-corrects, run continues
P3 Out-of-scope write via run_command (echo x > README.md) Passes the write tool, caught at settle
P4 Deletion without --allow-delete scope_violation, worktree kept
P5 Model commits in the worktree Diff vs base shows the true net change
P6 Model does nothing finish_no_diff, settled: false
P7 Crashed run left a worktree Preflight refuses, prints the cleanup command
P8 --carry-ignored asset, then teardown Source tree intact, verified by ls -la
P9 Backend returns HTTP 404 Error survives settle, not relabelled as a no-op
P10 Verify command writes __pycache__ Run settles; artifacts reported, out of the patch

P3, P5 and P6 pin the three ways a naive implementation would silently pass. P9 and P10 were added after the end-to-end run found both live.

Each guard is mutation-tested: settling against worktree HEAD instead of the base fails only P5, dropping the scope check fails only P3, treating an empty diff as a pass fails only P6, and removing the error guard fails only P9. A probe that cannot fail is not a check, and this is what proves these can.

Status

Built, ~230 lines, pure stdlib, no new dependencies, no change to the tool loop itself. --carry-ignored and --settle branch landed with the rest rather than later.

scripts/test_repo_mode.py runs 45 checks with no model calls. The existing suite (test_batch_empty, test_preflight, test_route_label, test_think_flag) still passes, so sandbox mode is unchanged.

Two latent bugs were fixed on the way: the module's scope globals were never reset between main() calls, so a second run in one process inherited the previous run's scope; and worktree names collided within a second.

End-to-end on z.ai glm-5.3: an off-by-one fix in 5 turns and 22s, a minimal one-line patch that applied clean with both tests passing, no out-of-scope writes. Logged to the ledger and verdicted good under code-edit.

That run also found a stale line in SKILL.md: the documented z.ai invocation omits --completions-path /chat/completions, and the default /v1/chat/completions 404s against the Coding Plan endpoint. Fixed in SKILL.md.
